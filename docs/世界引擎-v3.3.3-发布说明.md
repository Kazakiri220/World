# 世界引擎 v3.3.3 / 记忆引擎 v1.2.3

修复正在运行的请求保留旧 RPM 设置的问题。例如原来设为 1，请求提示还需等待 27 秒；此时保存为 0，旧版本仍会继续等待。现在等待中的请求约每秒检查本引擎最新保存的上限，设置为 0 或提高额度后可直接恢复，无需停止并重新开始任务。

全局 RPM 与供应商限流冷却分别显示。RPM=0 表示插件不主动限制请求数；供应商返回 429 等限流报错后，仍会按冷却时间等待，并显示对应连接及“供应商限流冷却中”。有可用的其他连接时继续切换，恢复请求后更新旧等待提示。

世界和记忆各自读取本引擎的设置，不会互相覆盖。

回归覆盖“剩余 27 秒时保存为 0”、提高额度、记忆旧快照、两个引擎隔离、RPM=0 时的供应商冷却、取消等待，以及完整浏览器面板中通过保存按钮让原请求恢复。验证使用离线响应，不调用真实供应商，也不修改聊天文件。

在本机实际酒馆页面验证时，保留旧 RPM=1 快照的请求在保存为 0 后，世界界面约 0.9 秒、记忆界面约 1 秒恢复。验证拦截聊天写入请求，全部 455 个聊天文件前后的 SHA-256 一致。
