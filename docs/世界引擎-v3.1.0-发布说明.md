# 世界引擎 v3.1.0

## API 连接管理

- 世界与记忆引擎的设置页均可新增、更新、删除和切换命名连接。现有配置会迁移为连接库中的旧连接。
- 两个引擎分别保存自己的选择。连接库保存地址、密钥、模型及直连/酒馆代理方式；请求参数仍使用各引擎自己的设置。
- 可选择酒馆 Connection Profiles，由酒馆按配置引用密钥发送请求，不切换正文使用的连接。该方式需要酒馆提供 `ConnectionManagerRequestService`。
- 酒馆配置的正文生成预设不参与插件请求；插件继续使用自己的提示词。支持连接测试。密钥不会进入世界历史或聊天备份。

## 范围更新与续传

- 起止范围、处理数量均按酒馆显示的聊天消息楼层计数，包含用户和 AI 消息；每批大小按 AI 回复数计数。
- 默认“继续补齐”，从最后成功处理的位置继续。结束楼层 0 表示最新 AI 回复，处理楼层数 0 表示不限。
- “指定范围重算”先恢复起点之前的世界，并替换此后的世界历史。原聊天正文不变。
- “从头重建”清空当前世界后重新推进，开始前尝试建立命名备份。
- 每批成功后同时保存世界结果和实际结束位置。中断、刷新、更换供应商后可点“继续上次任务”。若该任务的源聊天已变化，应按当前设置新建继续任务。
- 每批设为 1 可获得逐回复的恢复位置。较大的批次只产生批次末尾状态；范围起点落在合并批次内部时，需要改从该批起点处理或逐回复重建。

## 世界历史与回退

- 历史保存在消息自己的 `world_engine_history` 字段，基底保存在首条消息的 `world_engine_history_root` 字段；不替换整条消息、`extra` 或其他插件字段。
- 使用稳定消息及回复版本身份；每 20 个节点保存完整状态，其余采用差分。差分较大时直接保存完整状态。
- 删除聊天尾部时恢复仍保留的最后一份世界状态，不请求 API、不重新掷骰。没有发生世界更新的楼层沿用此前状态。
- 原生分支和 checkpoint 复制消息时携带世界历史；打开后根据实际保留的消息恢复，优先于复制来的最新 live 缓存。分支后的世界和后续主线分别保存。
- 手动编辑聊天正文不触发世界更新，也不会因此作废已有世界历史。
- 默认保留最近 200 个聊天楼层，可在范围更新设置中调整；0 表示不限。清理保留一个必要的完整基底，不删除正文和数据库存档。命名备份由原存档列表单独管理。
- 调大保留上限不能找回已清理的历史。删除到不可恢复的位置会停用世界注入和自动推演，需手动重建或恢复存档。
- 旧数据以可用的当前状态及滚动存档为升级基线；不会凭空生成升级前未保存的历史。手动恢复命名存档会在当前楼层建立新的历史基线。
- 世界信息仍通过独立的 In-Chat、depth 1、system 注入；历史快照不整批发送给正文模型。完善了数据库隔离前缀条目的过滤，本版不处理两插件叙事内容的冲突。

## 验证

新增离线测试覆盖连接迁移与隔离、酒馆配置请求、超时/取消、失败后刷新续传、真实楼层进度、分支独立推进、回复版本切换、删除回退、历史上限及差分基底、正文编辑不触发更新、范围重算、批次内部边界，以及删除或切聊天后的迟到响应。

未调用真实供应商 API，也未写入现有 SillyTavern 聊天文件。实际酒馆的界面操作与供应商连接仍需用户环境验证。
